3. PER-CALL COST
----------------
   First question in a subject (cache write):
     ~3,900 tokens written + 1,300 input + 800 output

     Worked example for DR (206k cache):
       Cache write: 206,000 × $18.75/M = $3.86
       Input:         1,300 × $15.00/M = $0.02
       Output:          800 × $75.00/M = $0.06
       TOTAL FIRST CALL                ≈ $3.94

   Each subsequent question within 5 min, same subject (cache read):
       Cache read:  206,000 × $1.50/M  = $0.31
       Input:         1,300 × $15.00/M = $0.02
       Output:          800 × $75.00/M = $0.06
       TOTAL CACHED CALL                ≈ $0.39

   First question after >5 min idle: cache expired → another write ≈ $3.94


4. RULE OF THUMB
----------------
   First call in a subject:        $1.10 – $7.30  (varies by subject size)
   Each subsequent call same subj: $0.20 – $0.65  (mostly the cache read)
   Output cost is negligible (~$0.06 per question regardless).

   The economics favour generating many questions per subject in one
   sitting. Generating just 1–2 questions per subject is wasteful because
   the cache load dominates.

7. COST-MINIMISATION TIPS
-------------------------
   - Run a plan in ONE sitting; cache expires after 5 minutes of idle.
   - The script auto-sorts targets by area so same-subject calls run
     back-to-back. Don't break that order.
   - If you only need 1–2 questions per subject, expect the cache
     overhead to dominate (≈ $2–$4 per subject regardless).
   - For LSy, both Legal System and Constitutional manuals are loaded
     (390k tokens) — this is the most expensive subject. Cluster all
     LSy work into a single uninterrupted run.
   - --dry-run still costs the API call. Use it once per subject to
     judge quality, then commit (or skip) the plan.

9. HYBRID: DEEPSEEK DRAFT + OPUS 4.8 VERIFY
-------------------------------------------
   Workflow:
     1. DeepSeek Pro drafts each question (cheap, may contain errors).
     2. Opus 4.8 reviews each draft against the SKILL and outputs
        either approval or a corrected version.

   Verification call token profile:
     Input  — drafted question to review (~1,400 tokens)
     Output — average of "approved + brief note" (~100 tokens) and
              "full rewrite + reasoning" (~1,000 tokens) ≈ 600 tokens

   Two verification depths:

   A) LIGHT VERIFY — Opus checks SKILL compliance only
      (skill.md + draft sent; relies on DeepSeek for legal accuracy)

      Skill block is cached (ephemeral cache_control), so the 2k
      skill is charged at cache-write rate on the first call and
      cache-read rate thereafter.

      Per call (observed, calibrated from a real verify run):
        Skill (cached after first call)        ~ $0.003 – $0.038
        Draft input      1,400 × $15.00/M     = $0.021
        Output           1,700 × $75.00/M     = $0.128
        TOTAL FIRST CALL                       ≈ $0.21
        TOTAL CACHED CALL                      ≈ $0.18

   B) HEAVY VERIFY — Opus checks SKILL + legal accuracy
      (skill + study materials + draft sent — same cached prefix as
      the original Opus drafting calls)

      Per call:
        First in subject  (cache write 150k system block)  ≈ $2.88
        Cached call       (cache read  150k system block)  ≈ $0.29

10. RECOMMENDATION
------------------
    - For BULK coverage (Plan B): hybrid with LIGHT verify saves the
      most ($17 vs $59, -71%). DeepSeek handles volume cheaply, Opus
      catches structural skill-compliance errors.
    - For TARGETED weakness drilling (Plans A, C): light verify also
      saves significantly (~$30) but the absolute spend is already
      modest. If you want maximum legal accuracy on your weakest
      topics, Opus-only is worth the extra dollars.
    - HEAVY verify defeats the cost advantage of DeepSeek almost
      entirely — only useful if DeepSeek's legal accuracy proves
      too unreliable to trust on the substance.
    - Best practice: PILOT 5–10 questions with each pipeline and
      manually compare quality before committing to a plan.


11. QUALITY CAVEATS — DEEPSEEK
------------------------------
    - DeepSeek Pro's English-and-Wales legal precision is unproven
      against Opus 4.8 — they performed measurably worse on the SQE1
      answer-the-question benchmark already run; drafting accuracy
      likely follows.
    - Structured JSON output is stricter on Anthropic. Expect higher
      parse-failure rates on DeepSeek; the verify step will catch
      structural defects but not all subtle errors.
    - The 3× output multiplier is conservative for an open-ended
      drafting task. If DeepSeek's reasoning is heavier here, scale
      DeepSeek totals upward by up to 1.5×.
